# Challenge record — E-007: merging heads without the transpose is invisible to shape checking

```text
Challenge:                  mha-explicit (tensor.ts) — the "not a twin" note; backend test
                            "a layout error the shape rules cannot see is caught by the
                            metamorphic pair (E-007)"
Source/paper:               —  (§12: "metamorphic pairs exist because shapes are not
                            semantics")
TENSA features stressed:     reshape element-count rule, the limits of dimension algebra
TENSA implementation:
    fn merge_heads(x: Tensor[B, Heads, T, DH]) -> Tensor[B, T, D] {
      return reshape(x, [B, T, D])          // transpose(x, 1, 2) forgotten
    }
Check result:               ok — Heads·T·DH = T·D is a true identity, so the reshape rule
                            proves the element count and the declared result type is
                            satisfied. No diagnostic is possible from shapes alone: the
                            program IS well-shaped, it just interleaves heads and time.
Runtime result:             runs, produces [B, T, D] — numerically wrong.
Metamorphic result:         mha-manual-vs-catalog fails: outputs differ from the catalog
                            attention at B=2, T=5 (the correct program agrees to 1e-4).
                            tests.ts asserts the pair rejects the broken merge.
Reference result:           PyTorch behaves identically (`.reshape(B, T, -1)` without the
                            transpose is a classic silent bug).
Finding classification:     E (design edge: the boundary of what static shape checking can
                            promise). NOT a checker defect — the checker's answer is
                            correct; the claim §12 makes is precisely that the metamorphic
                            layer exists for this class.
Severity:                   —  (recorded)
Workaround:                 the fn contract already forces the author to write the layout
                            twice (parameter + result); a metamorphic test against the
                            catalog op is the recommended discipline for hand-written
                            attention
Proposed action:            record only. If this class recurs across ≥3 substantially
                            different programs (§2.5), the G-class candidate is NAMED
                            AXES (reshape that must name which axes it merges), which
                            would refute this program at compile time. Not proposed now.
Language change required?:  no (candidate noted, evidence bar not met)
Regression test added?:     yes — backend / "… caught by the metamorphic pair (E-007)"
```
