# Challenge record — F-022: an optimizer without `over` covered only the first model

```text
Challenge:                  found by the tests.ts two-model plan while pinning H-008;
                            latent in `self-training`, `distillation` and every
                            multi-model plan that writes `optimizer opt = adamw(...)`
Source/paper:               —  (§17 lifecycle: "one optimizer, whole plan" is the
                            common case)
TENSA features stressed:     region-less optimizer, several `model` bindings in one plan
TENSA implementation:
    train T {
      model a = A
      model b = Bm
      loss la = L(y: a(x))
      loss lb = L(y: b(x))
      optimizer opt = adamw(lr: 1e-2)       # no `over`
      epochs 1
    }
Check result (before):      ok — and the optimizer's region text was the FIRST model
                            alias (`plan.models[0]`), so it claimed A's two tables and
                            none of B's. `lb` back-propagated into B every step and B
                            never moved; the emitted `opt_params = [a.p[k] for k in
                            [...]]` had the same omission. Nothing warned because the
                            F-017 check only asks whether an optimizer is APPLIED.
Check result (after):       a region-less optimizer has region `*` — every parameter of
                            every model bound in the plan. `resolveRegion` /
                            `paramsOfRegion` treat `*` as the union of all bound model
                            roots; the emitted list is grouped by owning alias
                            (`[a.p[k] for k in [...]] + [b.p[k] for k in [...]]`).
Runtime result:             4 tables in region `*`, all `updated` after two steps.
Reference result:           emitted plan trains both modules with one optimizer.
Finding classification:     F (default region was wrong)
Severity:                   major — silent partial training in the most ordinary plan
                            shape with two models
Workaround:                 write one optimizer `over` each model
Proposed action:            DONE — `analyze.ts` (`regionText = "*"`, `resolveRegion`),
                            `exec.ts` `paramsOfRegion`, `emit_torch.ts` `paramList`
                            groups by alias.
Language change required?:  no (the meaning of "no `over`" is now what the docs said)
Regression test added?:     yes — `lifecycle / a region-less optimizer covers every model
                            in the plan, not just the first (F-022)`
```
