# Challenge record — E-009: what the number in `ema(r)` means

```text
Challenge:                  state-zoo, state-shared-stage, state-in-scan
                            (`state center … update: ema(0.9)`), ema-teacher
                            (`track ema_t = ema(student, rate: 0.99)`)
Source/paper:               §14 state; BN running statistics, prototype/centre updates,
                            mean-teacher shadows
TENSA features stressed:     `state … update: ema(r)` in a model body; `track … =
                            ema(region, rate: r)` in a plan
Check result:               ok either way — the language never said whether `r` is the
                            weight kept from the PREVIOUS value (PyTorch EMA, TF
                            `ExponentialMovingAverage(decay)`, mean-teacher papers:
                            `next = r·cur + (1−r)·new`) or the weight of the NEW value
                            (BatchNorm's `momentum=0.1`: `next = (1−m)·cur + m·new`).
                            The reference runtime and the emitter each had a formula;
                            state-zoo was the first program to compare them against a
                            written expectation, and the reading had to be pinned before
                            the ema-teacher emitted shadow (`mul_(0.99).add_(…,
                            alpha=0.01)`) could be asserted.
Decision (2026-09-17):      `r` is the DECAY — the fraction kept: `ema(0.9)` keeps 90 %
                            of the previous value. This is the reading `ema(0.99)` has
                            in every EMA-teacher / Polyak-averaging paper and in
                            `torch.optim.swa_utils.AveragedModel`; BatchNorm's
                            "momentum" is the one outlier and TENSA does not use that
                            word. Both backends lower the same formula through one
                            helper (`emaDecay`).
Runtime result:             `exec.ts` state_update: `next = decay·cur + (1−decay)·new`
                            in training; frozen at eval. Tracked shadows likewise.
Reference result:           emitted `state_update`: `d * state + (1 - d) * value.detach()`;
                            tracked shadow: `v.mul_(d).add_(p.detach(), alpha=1-d)`.
Finding classification:     E (semantics were underspecified, not wrong)
Severity:                   minor (a convention), major if left implicit (0.9 vs 0.1 is
                            a 100× difference in time constant)
Proposed action:            DONE — one `emaDecay` helper shared by `exec.ts` and
                            `emit_torch.ts`; documented in docs.ts HARDENING.
Language change required?:  no (documentation of an existing form)
Regression test added?:     yes — challenge `ema-teacher` `emitContains`
                            `v.mul_(0.99).add_(student.p[k].detach(), alpha=0.01)`;
                            `state-zoo` state slots / checkpoint kinds
```
