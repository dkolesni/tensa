# Challenge record — F-001: rebound `let` name ties parameters

```text
Challenge:                  property `sharedStageCountInvariant` (src/lang/challenges/property.ts),
                            first generator version emitted N × `let y = Enc(x)`
Source/paper:               —  (surfaced by the property generator, protocol §38)
TENSA features stressed:     parameter identity (§8): independent vs. shared applications
Expected semantics:         `Enc(x)` written twice = two independent parameter sets
                            (documented by the siamese example / TwoTowers)
TENSA implementation:
    dim B
    block Enc(x: Tensor[B, 8]) -> Tensor[B, 8] { linear(8) ; gelu }
    model M(x: Tensor[B, 8]) -> Tensor[B, 8] {
      let y = Enc(x)
      let y = Enc(x)
      return y
    }
Check result:               ok, no diagnostics (before and after fix)
Inspect result (before):    2 tables, 72 values, both owned by `M/y/linear#1`,
                            `applications: 2`  → reported as SHARED
Inspect result (after):     4 tables, 144 values, owners `M/y/linear#1`, `M/y#2/linear#1`
IR result:                  same story as inspect (inspect is derived from IR)
Runtime result:             ran; second application used the first's weights
Reference result:           PyTorch: two `Enc()` constructions = two parameter sets
Gradient result:            n/a
Diagnostics:                none — that is part of the problem (see E-001)
Finding classification:     F (compiler bug). Secondary: E (shadowing undefined)
Severity:                   major — silent weight tying with no error is the
                            exact failure mode §8 warns about
Workaround:                 use distinct binding names
Proposed action:            DONE — `instantiate()` uniquifies a colliding instance
                            path with `#n`. Open question E-001: warn on
                            same-scope rebinding.
Language change required?:  no
Regression test added?:     yes — parameters / "rebinding a let name does not tie
                            parameters (F-001)"; property generator now uses
                            distinct names so it tests the invariant it claims.
```

Root cause: `analyze.ts` `instantiate()` built the instance path as
`${parent}/${nameHint}` for `let`-bound applications. Parameter ids are
`${path}/${op}#${n}.${role}`, and the application code treats an existing id as
"same parameter, another application". Two bindings with the same name therefore
produced the same ids and the second application was recorded as a *shared* use
of the first's tables.
