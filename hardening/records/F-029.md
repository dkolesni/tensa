# F-029 — BatchNorm running variance fidelity

Challenge: MoCo query/key BN state comparison on GPU.
Source/paper: BatchNorm running-statistics convention.
TENSA features stressed: persistent nonparameter state, training versus evaluation, checkpoint buffers.
Expected semantics: normalize using population variance; update running_var with unbiased estimate, matching generated F.batch_norm. Momentum is the weight of the new statistic, unlike explicit ema(decay).
TENSA implementation: exec multiplies batch variance by N/(N-1) for the persistent update only; singleton training refuses.
Check result: source and shape rules were already correct.
Inspect result: separate query/key running_mean and running_var slots unchanged.
IR result: state ownership unchanged.
Runtime result: [1,3] has population variance 1 and unbiased variance 2; initial running_var=1 with momentum=.1 becomes 1.1, not 1.0.
Reference result: CUDA train forward and persistent-buffer comparison now match; eval uses saved statistics unchanged.
Gradient result: normalization still uses population variance; forward gradients unaffected by detached running updates.
Diagnostics: runtime refusal for insufficient training samples, no new static code.
Finding classification: F, fixed 2026-09-18.
Severity: major cross-backend checkpoint/inference divergence.
Workaround: none.
Proposed action: keep buffer comparison, not just forward output checks.
Language change required?: no.
