# Challenge record — H-003: emitted PyTorch referenced symbolic extents as Python names / dictionary keys

```text
Challenge:                  unet-skip (semantic.ts), emit layer
Source/paper:               —  (§12 backend consistency)
TENSA features stressed:     derived dims (`dim H = 4 * K`) with runtime-bound K;
                            symbolic parameter/state shapes; `const_dim` in objectives
Expected semantics:         the generated module must import and construct for any
                            runtime dim binding; every symbolic extent must be
                            computed from the supplied bindings

                            import); non-constant parameter shapes emitted

                            shapes silently emitted extent `1`; `const_dim` of a
                            runtime dim emitted `1.0`
Backend result (after):     constants stay in STATIC_DIMS; `resolve_dims(dims)` computes
                            derived dims (`d["H"] = 4 * d["K"]`) after the runtime
                            bindings; `pyDim` renders any DimExpr as Python over a dims
                            dict (floordiv → `//`); objectives take `dims=None` and the
                            training plan passes its bindings through
Finding classification:     H (backend)
Severity:                   major — every program with a derived dim over a runtime dim
                            produced a non-importable file; the reference runtime was
                            unaffected, so §12 consistency was silently broken
Proposed action:            DONE (emit_torch.ts)
Language change required?:  no
Regression test added?:     yes — backend / "symbolic extents lower to Python expressions,
                            not dictionary keys (H-003)"; challenge:unet-skip emit layer
```
