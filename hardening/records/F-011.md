# Challenge record — F-011: slice and index bounds were never checked

```text
Challenge:                  slicing-torture / window-bound-runtime (tensor.ts), twins
                            slice-past-end / index-at-extent / start-after-end /
                            constant-axis-overrun
Source/paper:               —  (§5.3 reshape / transpose / slicing with symbolic dims)
TENSA features stressed:     slicing with symbolic bounds (`x[:, 1:T, :]`, `x[:, 2:W+2, :]`),
                            indexing (`x[:, 0, :]`, `x[:, T, :]`), carried constraints (§5.2)
Expected semantics:         a slice `a:b` on an axis of extent N requires 0 ≤ a ≤ b ≤ N;
                            an index i requires 0 ≤ i < N. Proved when the algebra can,
                            refuted when it never holds, carried (and enforced at runtime)
                            otherwise — the same four-outcome discipline as equality.
TENSA implementation:
    dim B
    dim T
    dim D = 8
    model Over(x: Tensor[B, T, D]) -> Tensor[B, T + 1, D] { return x[:, 0:T+1, :] }
    model At(x: Tensor[B, T, D]) -> Tensor[B, D] { return x[:, T, :] }
Check result (before):      ok, no diagnostics — the slice was typed Tensor[B, T + 1, 8]
                            and the index accepted; the runtime then read past the operand
                            (the slice op had no bounds guard either).
Check result (after):       Over → error AXS0410 "slice end on axis 1 (must be ≤ extent):
                            T + 1 exceeds T · the range overshoots by 1".
                            At → AXS0410 "index on axis 1 (must be < extent): T + 1
                            exceeds T". `x[:, 3:1, :]` → AXS0410 "start must not exceed
                            end". `x[:, 0:W+2, :]` with free T → warning AXS0403
                            "cannot prove W + 2 ≤ T", carried as `W + 2 ≤ T`.
Runtime result (after):     window-bound-runtime binds T=3 → "carried constraint violated:
                            slice end on axis 1 (must be ≤ extent): 4 ≤ T but 4 > 3",
                            refused before any forward pass; T=5 runs. Independently the
                            runtime slice throws "slice [a:b] is out of bounds for axis k
                            of extent N" if a bound ever reaches it unchecked.
Reference result:           PyTorch silently clamps `x[:, 0:T+1]` to T (a quiet shape
                            change) and raises IndexError for `x[:, T]` at runtime only.
Finding classification:     F (missing constraint = false certainty; a wrong static shape)
Severity:                   major — the derived shape Tensor[B, T + 1, D] was simply wrong
Proposed action:            DONE — `analyze.ts` `leDim(a, b, origin)`: difference b − a is
                            proved non-negative (all coefficients ≥ 0, or a negative
                            constant covered by positive plain-variable monomials, since
                            every dim is ≥ 1), refuted (all coefficients < 0 and
                            `isNonZero`) → AXS0410, or carried as a constraint with
                            `rel: "<="` (new field on `ir.ts` `Constraint`, printed `≤` by
                            inspect / printIR) → AXS0403; `exec.ts` `checkConstraints`
                            evaluates `≤` constraints alongside `=`.
Language change required?:  no (new diagnostic code AXS0410 "index out of bounds", added
                            at the end of the 04xx range)
Regression test added?:     yes — shapes / "slice bounds are proved, refuted or carried as
                            ≤ constraints (F-011)"; challenge:slicing-torture (8 models,
                            carriedExactly on the three window ends, 6 twins);
                            challenge:window-bound-runtime; metamorphic
                            open-vs-explicit-slice
```
