# Challenge record — F-014: an update whose optimizer reached only frozen parameters trained nothing

```text
Challenge:                  transfer-lifecycle (twin `frozen-but-updated`)
Source/paper:               fine-tuning recipe: freeze backbone, warm the head, unfreeze
                            (§17 lifecycle, §26 escalation ladder item 4)
TENSA features stressed:     `freeze` / `unfreeze` per phase, optimizers `over` a region,
                            `update <loss> with <optimizer>`
TENSA implementation:
    train Finetune {
      model Net = Transfer                 # let encoder = Backbone(); let head = Head()
      optimizer head_opt = adamw(lr: 1e-3) over Net.head
      optimizer enc_opt  = adamw(lr: 1e-5) over Net.encoder
      phase warmup { epochs 2  freeze Net.encoder  update main with enc_opt }
      ...
    }
Check result (before):      ok — the warmup phase compiled, ran, and reported every
                            encoder table as "frozen"; the head, which the recipe
                            meant to warm, never moved. Nothing pointed at the update.
Check result (after):       AXS0704 error at the phase: "phase 'warmup' updates 'main'
                            with 'enc_opt', but every parameter it covers is frozen in
                            this phase" (note: unfreeze the region, or update with an
                            optimizer over a trainable region).
Runtime result:             (after) refused at compile time; the un-mutated challenge
                            runs warmup (12 steps) and finetune (18 steps) and reports
                            every encoder table updated once unfrozen (gradCoverage).
Reference result:           PyTorch raises nothing either — a param group of tensors
                            with requires_grad=False is a silent no-op — which is
                            exactly why the language has to say it.
Finding classification:     F (the lifecycle contract "an update trains something" was
                            not checked)
Severity:                   major — a phase that trains nothing looks identical to one
                            that trains
Workaround:                 read the inspect lifecycle table per phase
Proposed action:            DONE — `analyze.ts` plan checking: for every phase update,
                            collect the parameters its optimizers reach; if all of them
                            are frozen in that phase, AXS0704.
Language change required?:  no
Regression test added?:     yes — challenge `transfer-lifecycle` twin
                            `frozen-but-updated` (expects AXS0704)
```
